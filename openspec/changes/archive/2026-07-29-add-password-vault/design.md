## Context

移动端当前使用 Expo 57、React Native、SQLite 和应用沙盒文件系统。结构化数据通过 `SQLiteProvider` 打开 `still-alive.db`；本地导出把快照序列化为可读 `data.json`，同时导出 Markdown 与媒体文件。项目已安装的 `expo-crypto` 目前只用于备份摘要，仓库没有系统安全存储或生物识别接入。

密码本与日记的安全目标不同：日记备份强调可读和可迁移，密码本必须在设备文件或 ZIP 被复制时仍保持不可读。因此不能把密码条目加入现有普通表、设置键值或 `BackupSnapshot`，也不能把主密码保存到 SQLite、设置、SecureStore 或备份中。

已确认的产品选择：独立主密码为必选，系统指纹或面容仅作为可选快捷解锁。首版只服务本机个人使用，不提供账号体系、同步、自动填充、浏览器插件、密码生成器、分享或明文导出。

## Goals / Non-Goals

**Goals:**

- 设备数据库、沙盒文件或 ZIP 备份被复制后，攻击者无法直接读取密码条目。
- 主密码不落盘；正确主密码或已启用的本机生物识别凭据是解锁密码本的唯一入口。
- 所有条目字段统一加密，避免通过名称、网址或备注泄露用户使用的服务。
- 锁定、退出、备份恢复和删除行为明确且不会静默丢失当前密码本。
- 保持实现局部，不改变日记、人物、媒体和现有可读导出的业务语义。

**Non-Goals:**

- 不防御已经控制应用进程、系统、输入法或无障碍服务的攻击者，也不承诺在越狱/root 设备上提供完整保护。
- 不实现网站或其他应用的自动填充，不导入浏览器/第三方密码管理器数据。
- 不实现跨设备同步、云端账号、共享保险库、密码分享或服务端恢复。
- 不实现密码生成器、泄露检测、密码健康评分、TOTP 或附件。
- 不加密现有日记数据库和媒体；它们继续遵循现有本地沙箱与可读导出约定。
- 不保证 JavaScript 运行时能物理擦除所有历史字符串；锁定时只做可实现的引用释放和二进制缓冲区覆写。

## Threat Model

本变更主要防御两类离线泄露：他人取得应用沙盒中的密码本文件，或取得用户导出的 ZIP。它也减少应用进入后台、任务切换和误复制时的偶然暴露。

本变更不防御已解锁会话中的肩窥、恶意输入法、系统被攻破、运行时注入或用户主动把密码粘贴到不可信位置。界面和说明不得把“本地加密”描述为对所有攻击都安全。

## Decisions

### 1. 密码本使用独立加密信封文件，不进入现有明文数据模型

密码本保存为应用沙盒内的 `vault.enc`。文件外层只包含版本、KDF 参数、随机盐、包裹后的数据密钥、随机 nonce 和密文；条目数量、名称、账号、网址、备注与时间戳都位于密文载荷中。

解密后的载荷版本 1 为：

```ts
interface PasswordVaultPayloadV1 {
  schemaVersion: 1;
  entries: Array<{
    id: string;
    name: string;
    username: string;
    password: string;
    url: string;
    note: string;
    createdAt: string;
    updatedAt: string;
  }>;
}
```

每次修改都在内存中生成完整新载荷，使用新 nonce 加密，写入临时文件并验证可读后再替换正式文件。具体文件替换语义必须按当前 Expo 文件系统的真实能力验证；若不能保证原子替换，必须保留可回滚的上一份有效密文，不能直接覆盖唯一副本。

选择单一加密信封而不是逐条 SQLite 加密，是因为个人密码本预期体量小，整包读写更容易保证所有字段都加密、减少明文索引与迁移面，并避免被现有 `BackupSnapshot` 自动序列化。若未来条目规模或并发写入出现真实性能问题，再单独设计分块格式。

### 2. 使用数据密钥与主密码派生密钥分层加密

创建密码本时生成随机 256 位数据密钥（DEK）。主密码通过版本化、带随机盐的内存困难 KDF 派生密钥加密密钥（KEK），KEK 只用于包裹 DEK；DEK 使用带认证加密（AEAD）加密密码本载荷。

版本 1 优先采用 Argon2id 和维护中的 AEAD 实现。具体密码学包、算法参数、nonce 长度和可用平台必须在实施第一步通过真实的 Expo 57/iOS/Android 兼容性记录确认；如无法找到维护中且可真机构建的实现，应停止实施并报告，不能退回自写算法、普通 SHA-256、单轮 hash、固定 nonce 或无认证加密。

KDF 参数随信封保存并设定允许的上下界，导入时先校验再派生，避免恶意备份声明极端参数造成资源耗尽。参数目标是在代表性中端真机上达到可接受的交互延迟并显著增加离线猜测成本；最终数值以选定实现和真机测量为准。主密码按用户输入的精确 UTF-8 内容处理，不自动 trim 或改变大小写。

包裹 DEK 与加密载荷使用不同的关联数据域，并为每次加密生成独立随机 nonce。AEAD 验证失败统一显示“主密码不正确或密码本已损坏”，不得返回部分内容。

实施固定记录：AEAD 使用现有 `expo-crypto@57.0.1` 的原生 AES-256-GCM（MIT），数据密钥 32 字节、nonce 12 字节、认证标签 16 字节；KDF 使用 `@noble/hashes@1.8.0` 的 Argon2id（MIT，纯 JavaScript，该包 README 明确标注 Argon2 实现未包含在其既有审计范围）。版本 1 当前写入参数为 16 字节随机盐、16 MiB 内存、2 次迭代、并行度 1、输出 32 字节；解析只接受 16–256 MiB、1–10 次迭代、并行度 1–4、输出 32 字节，信封和解密载荷上限分别为 4 MiB 与 3 MiB。16 MiB 是任务 1.3 完成代表性 iOS/Android 真机测量前的兼容参数，最终发布参数仍须以真机结果为准。

### 3. 生物识别只保存本机快捷解锁材料

用户用主密码成功解锁后可主动开启指纹或面容快捷解锁。系统安全存储只保存受设备用户认证保护的 DEK，不保存主密码、KEK 或解密后的条目；该材料不进入 ZIP，也不参与跨设备恢复。

启用和使用快捷解锁前都要走操作系统认证。认证能力不可用、用户取消、系统凭据失效、重装或更换设备时，界面回退到主密码解锁。关闭快捷解锁时立即删除系统安全存储中的材料。

修改主密码必须在已解锁状态再次验证当前主密码，然后用新 KEK 重新包裹同一 DEK；载荷无需因换主密码而改变。忘记主密码不提供重置或后门，即使本机生物识别仍能临时解锁，也不能绕过当前主密码修改主密码。

系统能力固定为 `expo-secure-store@57.0.1`（MIT）的 `requireAuthentication` 与 `canUseBiometricAuthentication()`；iOS 配置 `NSFaceIDUsageDescription`，Android 使用插件生成排除安全存储材料的系统备份规则。剪贴板使用 `expo-clipboard@57.0.1`（MIT）的读取/写入接口；页面与任务切换保护使用 `expo-screen-capture@57.0.1`（MIT）的截图录屏阻止和 iOS App Switcher 遮罩。未加入 `expo-local-authentication`，因为本变更所需认证已由 SecureStore 覆盖。

### 4. 解锁会话限制在密码本模块内

密码本使用独立的路由级状态容器，不把解密载荷加入全局 `AppStateProvider`。进入模块时解锁，在模块内的列表与编辑页面间共享同一次会话；离开模块、应用进入 `inactive/background`、组件卸载或发生不可恢复错误时立即锁定。

锁定时清空解密条目引用，并对仍持有的 DEK/KEK 二进制缓冲区做尽力覆写。导航参数只传随机条目 ID，不传名称、账号或密码。日志、异常、埋点、通知和可访问性标签不得包含密码内容。

密码本页面在非活跃状态先显示不含内容的隐私遮罩。iOS/Android 真机必须验证系统任务切换预览不包含条目或密码；若 React Native 生命周期无法可靠满足，才允许加入完成该要求所必需的平台能力，且必须记录新增依赖原因。

### 5. 备份只携带密文，恢复密码本独立确认

现有 ZIP 的 `data.json`、Markdown 和媒体结构保持不变。存在密码本时额外加入原始 `vault.enc`，manifest 继续记录其摘要；`readme` 或界面说明该文件只能由「仍在」配合对应主密码恢复。禁止生成明文密码清单。

普通日记恢复和密码本恢复分开处理：

- 备份没有 `vault.enc` 时，保留当前密码本，不静默删除。
- 备份包含 `vault.enc` 时，先校验路径、大小、manifest 摘要、格式版本和 KDF 参数边界，再要求输入该备份的主密码并完成 AEAD 解密验证。
- 当前设备已有密码本时，还要先解锁当前密码本并单独确认替换；取消或任何校验失败都保持当前密码本不变。
- 恢复成功后写入加密信封，但不恢复生物识别材料；用户需用主密码进入后重新开启快捷解锁。

单个密码本信封设置合理大小上限，避免导入任意大文件耗尽内存；最终上限与错误文案在实现时结合载荷结构固定，不接受无界输入。

### 6. 界面仅提供最小密码管理操作

「我的」页面新增一张密码本入口卡。模块内只包含首次设置/解锁、条目列表、新建、查看/编辑、删除和密码本安全设置。

名称与密码必填；账号、网址、备注可选。密码输入默认使用安全文本模式，关闭自动纠正和自动大写。列表只显示解锁后得到的名称与账号，密码默认遮蔽；显示密码是当前页面的临时状态，离开页面或锁定后恢复遮蔽。

复制密码必须由用户主动触发。复制后显示明确的 60 秒提示；定时清理只能在确认剪贴板仍是本次复制内容时执行，不能清除用户随后复制的其他内容。若目标平台无法在不产生额外隐私副作用的情况下可靠比较剪贴板，必须基于真实平台记录调整实现和文案，不能伪称已自动清理。

### 7. 删除采用密码本独立确认并覆盖全量删除路径

删除单条记录需要确认。删除整个密码本需要已解锁状态下再次输入主密码，并明确说明所有保存的账号密码不可恢复；完成后删除加密信封、临时/回滚文件和系统安全存储材料。

解锁页的“忘记主密码”只允许删除密码本并重新创建，不影响日记、人物和媒体；此路径需要输入固定确认文本或等价的高强度二次确认。「删除全部本地数据」也必须明确包含并删除密码本，不能只清 SQLite。

## Risks / Trade-offs

- **密码学依赖与 Expo 57 兼容性尚未验证** → 实施第一项必须取得真实版本、构建和 API 记录；无法确认时停止，不用试错请求或自写替代。
- **主密码遗忘会永久失去数据** → 首次设置、修改和备份说明都明确告知；主密码输入两次确认，但不增加服务端恢复后门。
- **JavaScript 内存无法保证完整清零** → 缩小解锁状态作用域、后台立即锁定、尽力覆写二进制密钥，并准确声明威胁边界。
- **整包加密每次编辑都会重写文件** → 个人文本条目体量小，先接受简单实现；通过临时文件与恢复验证避免写入中断损坏唯一副本。
- **生物识别材料可能因系统状态变化失效** → 主密码始终保留为根解锁方式，恢复或换机后需要重新启用。
- **剪贴板行为在平台间不同** → 只有真机验证可靠后才宣称自动清理，且绝不覆盖用户后来复制的内容。
- **备份恢复可能覆盖现有密码本** → 密码本独立解锁、校验和确认，普通日记恢复默认保留当前密码本。
- **加入密码学会影响发布声明** → 根据最终实现重新核对 `ITSAppUsesNonExemptEncryption` 和商店申报，不沿用当前值做假设。

## Migration Plan

1. 验证并确定 Expo 57 可用的密码学、安全存储、生物识别与剪贴板实现，固定信封格式和参数边界。
2. 增加密码本领域模型、加密信封编解码与独立文件存储适配器；不迁移现有 SQLite 数据。
3. 增加路由级解锁会话、主密码设置/解锁/修改和可选生物识别材料管理。
4. 增加「我的」入口、条目列表与编辑页面，并接入自动锁定、遮罩和剪贴板保护。
5. 扩展 ZIP 导出/恢复和全量删除流程，确保密码条目永不进入 `data.json` 或 Markdown。
6. 运行类型检查和静态构建，并在 iOS/Android 真机验证生命周期、生物识别、任务切换预览、剪贴板和备份往返。

若发布后需要回滚界面，保留 `vault.enc` 文件且不读取，避免降级版本删除用户密码；再次升级后仍可按版本恢复。只有用户明确删除密码本或全部本地数据时才删除该文件。

## Open Questions

无产品阻塞项。密码学与平台模块的具体包版本、KDF 参数和文件替换能力属于实施前必须用真实兼容性记录关闭的技术门槛。
