# 产品需求文档 (PRD) - 还活着 / Still Alive

> "还活着吗？"——一款以生存确认和记忆沉淀为核心的多端打卡应用。

---

## 1. 产品概述

### 1.1 产品定位

"还活着"是一款以**生存确认**和**记忆沉淀**为核心的打卡工具。它通过轻量化的每日互动，引导用户记录生活中的意义，为重要的人建立情感档案，并通过匿名故事社区连接更广泛的生命叙事。

| 维度 | 说明 |
|------|------|
| 核心驱动 | "活着"的自我感知 + "记忆"的主动构建 + "韧性"的集体见证 |
| 工具定位 | 打卡工具，支持"什么都不记录"的纯粹打卡 |
| 情感连接 | 通过文字记录对抗遗忘，将重要的人和事内化为持久的记忆 |
| 公共空间 | 匿名故事社区，收录"差点就没了，但我现在还活着"的瞬间 |

### 1.2 目标用户

- 希望养成每日反思习惯的用户
- 想要记录生活中有意义时刻的用户
- 希望建立人际关系档案、珍惜重要人物的用户
- 愿意分享或阅读生命韧性故事的用户

### 1.3 核心价值观

| 价值观 | 说明 |
|--------|------|
| 轻量化 | 不强求过度记录，支持纯粹打卡 |
| 正向引导 | 所有反馈文案温和、非压力式 |
| 情感连接 | 通过文字记录对抗遗忘 |
| 记忆深化 | 写下来本身就是加深记忆的过程 |
| 生命韧性 | 关注"活下来之后"，而非死亡本身 |

### 1.4 多端形态

| 端 | 技术栈 | 功能范围 |
|----|--------|----------|
| iOS / Android | React Native | 全功能 |
| Web | React (SPA) | 全功能 + 故事 SEO 独立路由 |
| 微信小程序 | Taro (React) | 核心功能（打卡、人物、故事浏览+共鸣，**不含故事投稿**） |

三端共享 TypeScript 接口定义、API 请求层、纯函数工具库和设计 Token，UI 组件各端自行实现。

## 2. 产品架构

### 2.1 导航结构（4 Tab）

| Tab | 名称 | 图标 | 核心定位 |
|-----|------|------|----------|
| 1 | 主页 | `house-chimney` | 核心入口，快速打卡、故事入口、信息聚合 |
| 2 | 打卡 | `calendar-check` | 打卡记录管理与历史回顾 |
| 3 | 人物 | `address-book` | 人物小传与情感档案管理 |

### 3.4 故事模块（融合 still-alive.com）

故事模块是匿名生命韧性故事社区，收录"差点就没了，但我现在还活着"的瞬间。

#### 3.4.1 设计哲学

| 原则 | 说明 |
|------|------|
| 不贩卖焦虑 | 关注"活下来之后"，而非死亡本身 |
| 只陈列韧性 | 每一则故事都是一个"仍在"的证明 |
| 设计退场 | 界面退到背后，让文字成为唯一主角 |
| 无评论区 | 保持安静，只有共鸣和分享 |

#### 3.4.2 故事流

| 功能点 | 说明 |
|--------|------|
| 列表展示 | 卡片式故事预览，正文预览约 3 行 |
| 滚动加载 | 无分页，每次加载 10 则 |
| 展开阅读 | 点击原地展开全文（移动端进入详情页） |
| 分类筛选 | 意外与事故 / 疾病与康复 / 心理与精神 / 自然与极限 / 其他 |
| 随机故事 | 摇一摇或按钮随机跳转 |

#### 3.4.3 故事详情

| 功能点 | 说明 |
|--------|------|
| 沉浸阅读 | 最大宽度 640px，居中排版，衬线字体 |
| 共鸣按钮 | 心跳波形图标，文案"感同身受"，无需登录 |
| 分享 | 复制纯文字 / 生成分享图片（深色背景 + 白色文字卡片） |
| 内容警告 | 涉及敏感内容的故事展开前显示确认提示 |
| 心理援助 | 敏感故事文末附加心理援助热线 |

#### 3.4.4 故事投稿

| 功能点 | 说明 | 平台支持 |
|--------|------|----------|
| 正文 | 必填，100&ndash;800 字 | App + Web |
| 标题 / 首句 | 选填，&le; 30 字 | App + Web |
| 大致时间 | 选填，自由文本 | App + Web |
| 故事类型 | 选填，单选分类 | App + Web |
| 联系邮箱 | 选填，仅用于审核通知 | App + Web |
| 投稿权限 | 登录用户直接投稿；未登录用户亦可投稿 | App + Web |
| 小程序 | **不支持投稿**，仅浏览 + 共鸣 | 小程序 |
| 提交反馈 | "已收到，感谢你把这一刻分享给我们。" | - |

#### 3.4.5 故事审核

| 规则 | 说明 |
|------|------|
| 审核时效 | 48 小时内完成审核 |
| 通过标准 | 聚焦存活后感受、第一人称真实叙述、温暖语气 |
| 拒绝标准 | 详述死亡手段、虚构故事、含可识别个人信息、仇恨内容 |
| 审核通知 | 有邮箱则邮件通知审核结果 |
| 管理入口 | 后台管理页面（仅管理员可访问） |

#### 3.4.6 共鸣交互

| 功能点 | 说明 |
|--------|------|
| 图标 | 心跳波形 SVG 动画 |
| 文案 | "感同身受" |
| 未登录 | 基于设备标识 / localStorage 防重复 |
| 已登录 | 记录到用户账户 |
| 显示格式 | &hearts; N 人感同身受 |

#### 3.4.7 Web 端独立路由

| 路由 | 说明 |
|------|------|
| `/stories` | 故事流首页，支持未登录访问，SSR/SSG 友好 |
| `/stories/:id` | 故事详情页，支持分享链接直接访问 |
| `/stories/submit` | 投稿页 |
| `/stories/random` | 随机故事 |

#### 3.4.8 故事内容安全

所有涉及抑郁、自杀的故事，文末自动附加：

```
如果你正在经历类似的时刻，请联系：
北京心理危机研究与干预中心：010-82951332
全国心理援助热线：400-161-9995
生命热线：400-821-1215
```

## 4. 业务规则

### 4.1 打卡规则

| 规则 | 说明 |
|------|------|
| 打卡周期 | 每日 0:00&ndash;23:59 为一个打卡周期 |
| 打卡次数 | 每日仅可打卡一次 |
| 连续计算 | 连续天数从第一次打卡开始累计，中断后重新计算 |
| 补签规则 | 仅可补签过去 7 天内的记录，每月最多 3 次 |
| 幂等性 | (user_id, date) 为唯一键，重复打卡幂等返回成功 |

### 4.2 提醒规则

| 规则 | 说明 |
|------|------|
| 打卡提醒 | 用户自定义时间，默认 21:00 |
| 生日提醒 | 仅在生日当天提醒 |
| 死亡确认 | 连续 N 天未打卡后发送邮件（用户可配置 N） |

### 4.3 文案规则

| 场景 | 文案 |
|------|------|
| 待打卡状态 | "还活着吗？" |
| 打卡成功 | "恭喜你又活过了一天！" |
| 昨日未打卡 | "一定是因为昨天过得很开心吧，才忘了打卡" |
| 连续未打卡 | "好久不见，你还好吗？" |
| 里程碑 7 天 | "连续7天，你是真的在认真活着" |
| 里程碑 30 天 | "一个月了，生活在继续" |
| 里程碑 100 天 | "100天，你已经证明了自己" |
| 里程碑 365 天 | "一整年，这是属于你的史诗" |
| 故事投稿成功 | "已收到，感谢你把这一刻分享给我们。" |
| 故事共鸣 | "&hearts; N 人感同身受" |
| 故事 404 | "这一页不见了，但你还在。" |

### 4.4 故事审核规则

| 通过 &check; | 拒绝 &cross; |
|--------|--------|
| 聚焦于存活后的感受与细节 | 详述死亡手段（尤其自杀方法） |
| 第一人称真实叙述 | 虚构或明显捏造的故事 |
| 匿名或化名保护隐私 | 含真实姓名、可识别地点信息 |
| 温暖 / 诗意 / 平静 / 幽默的语气 | 仇恨、歧视或攻击性内容 |

## 8. 内容安全与隐私

### 8.1 心理健康提示

所有涉及抑郁、自杀的故事，文末自动附加心理援助热线信息。措辞克制，不说教。

### 8.2 隐私保护

| 规则 | 说明 |
|------|------|
| 故事匿名 | 故事展示时不关联作者信息 |
| 邮箱隔离 | 投稿邮箱仅用于通知，不与故事内容关联存储 |
| 无第三方追踪 | 不使用第三方统计工具 |
| 数据安全 | 用户私人数据加密存储，传输全程 HTTPS |

### 8.3 小程序 UGC 合规

微信小程序不支持投稿功能，规避 UGC 审核风险。故事内容由后台审核后推送，属于"运营内容展示"。
