# 产品需求文档 V3 — 仍在 / Still Alive

> 每天留下一点，慢慢得到一份属于自己的生命档案。

| 项目 | 内容 |
|---|---|
| 文档状态 | 已同步当前实现 |
| 实现基线 | v1.0.6（2026-08-13） |
| 产品阶段 | MVP 已发布迭代，音乐与阅读已进入当前实现 |
| 核心定位 | 本地优先的个人生命记录工具 |
| 核心闭环 | 打卡 → Markdown 日记 → 图片/语音/地点/人物关联 → 时间沉淀 → 回看 |

---

## 1. 产品结论

「仍在」不是连续打卡挑战，也不是要求用户每天认真写作的日记应用。

它通过一次低成本的每日确认，帮助用户逐渐留下生活片段，并按时间与人物自动组织。随着记录累积，产品最终形成一份可回看、可迁移、属于用户自己的生命档案。

产品的长期价值不来自连续天数，而来自三件事：

1. 让记录足够容易开始。
2. 让零散内容自动形成时间和人物脉络。
3. 让过去的记录在合适的时间重新出现。

## 2. 问题与机会

### 2.1 用户问题

- 传统日记的写作门槛高，用户很难长期坚持。
- 相册记录了画面，但缺少当时的感受、人物和背景。
- 笔记工具擅长保存内容，但不擅长形成个人生命脉络。
- 重要人物的共同经历散落在聊天、照片和记忆中，难以回看。
- 私密记录放在第三方平台时，用户担心泄露、停服和无法迁移。

### 2.2 产品机会

用「打卡」降低每天打开产品的成本，用「写一条」承接偶发的表达欲，再通过人物关联和回忆触发，让内容随时间产生复利。

## 3. 产品目标

### 3.1 MVP 目标

- 用户能在 5 秒内完成当天打卡。
- 用户打卡后能自然地写下一条可选记录。
- 用户能用适合移动端的全屏所见即所得编辑器记录文字、图片和语音，正文仍以 Markdown 保存。
- 用户可在打卡时记录城市，并为日记保存当前位置或自定义地点文字。
- 用户能把记录关联到一个或多个人物。
- 用户能通过日历、人物和相册整理与回看历史内容。
- 用户能记录自己与人物的生日、标签和基础资料，并获得可控的本地提醒。
- 用户能在音乐盒中保存并播放自己的音乐，也能为人物维护喜欢的音乐。
- 用户能从「我的」进入书架，导入、管理和阅读本地电子书，并沉淀摘抄与读书笔记。
- 用户能完整导出自己的数据和媒体文件。
- 用户中断使用后能够无压力地重新开始。

### 3.2 非目标

MVP 不包含：

- 公共故事社区、关注、评论、私信等社交功能。
- 排行榜、积分、断签惩罚等游戏化机制。
- 人物关系图、人物之间的连线和独立事件模型。
- WebDAV、S3 等高级云同步配置。
- 多设备实时双向同步和冲突合并。
- AI 自动总结、心理分析或人物关系判断。
- 未打卡后向紧急联系人发送生存或死亡确认。

## 4. 目标用户

### 4.1 核心用户

- 想记录生活，但无法坚持写长日记的人。
- 希望长期保存孩子、伴侣、父母或朋友共同经历的人。
- 正处于毕业、迁居、恋爱、育儿、照护等人生阶段的人。
- 重视隐私、数据所有权和长期可迁移性的人。

### 4.2 不优先服务的用户

- 主要诉求是公开表达和获得互动反馈的用户。
- 需要团队知识管理或专业笔记编辑能力的用户。
- 只关心习惯追踪、目标管理和效率统计的用户。

## 5. 核心原则

### 5.1 记录没有负担

- 打卡由一次主要操作发起；城市定位可跳过，不阻塞完成。
- 写作永远可选。
- 不设置最低字数。
- 不因断签制造损失感、羞耻感或焦虑。

### 5.2 历史内容必须重新产生价值

产品不能只负责保存。它需要通过「那年今日」、人物回忆和阶段回顾，让用户重新遇见过去的内容。

### 5.3 人物关联优于人物维护

用户主要在写记录时顺手关联人物。人物档案由历史记录逐渐形成，不要求用户预先填写大量资料。

### 5.4 数据默认属于用户

- 私密内容默认保存在本地设备。
- 数据可完整导出，格式有文档说明且不依赖本产品才能读取。
- MVP 不以无法迁移的数据锁定用户。

### 5.5 文案温和、明确

- 不使用「必须」「立即」「失败」「断签」「失联」「死亡确认」等施压词汇。
- 用户中断后返回，默认文案为「今天也可以重新开始」。
- 连续天数是信息，不是评价。

## 6. 核心用户旅程

### 6.1 第一次使用

1. 用户进入产品，看到一句定位说明和本地存储说明。
2. 用户选择是否设置昵称和出生日期；均可跳过。
3. 用户进入空间页。
4. 页面顶部只突出一个主要动作：「今天也在」。
5. 完成后出现可选动作：「想留下一点什么吗？」

首次使用不强制注册、不强制创建人物、不强制配置备份。

### 6.2 日常使用

1. 打开空间页。
2. 点击「今天也在」。
3. 可直接离开，也可写下一条记录。
4. 写记录时可添加图片、语音、地点并关联人物。
5. 保存后回到空间，看到今天的内容已经沉淀在全部历史记录中。

### 6.3 回看

1. 空间在存在历史内容时展示一条回忆入口。
2. 用户可查看「那年今日」或与某个人相关的过去记录。
3. 用户可以补充当时的背景，但不修改原始创建时间。

### 6.4 中断后返回

1. 不弹出断签警告。
2. 不要求补签。
3. 显示「欢迎回来，今天也可以重新开始」。
4. 用户完成当天打卡后恢复正常流程。

## 7. 信息架构

MVP 使用四个一级入口：

| 入口 | 作用 |
|---|---|
| 空间 | 当前打卡、写记录、提示内容、全部历史记录 |
| 日历 | 月历、记录日期标记、按月份回看 |
| 人物 | 人物列表及人物记忆页 |
| 我的 | 个人资料、个人相册、音乐盒、我的书架、密码本、设置与数据管理 |

「写一条」不是一级导航。它只在完成当天打卡后出现，也可以从某个历史日期或人物页进入。四个一级入口保持稳定，不增加独立编辑器 Tab。

## 8. 功能需求

### 8.1 空间状态与历史入口

空间页顶部卡片可以在三个打卡状态与“记忆追踪”数据间点击切换，卡片下方始终展示全部历史记录。

#### 状态 A：今天未打卡

- 顶部卡片显示当前日期。
- 首次使用时显示产品引导。
- 主要按钮：「今天也在」。
- 不展示连续天数压力文案。
- 不展示写作入口，直到完成当天打卡。

#### 状态 B：已打卡、今天未记录

- 显示「今天已留下一个小小的坐标」。
- 次要按钮：「写一条记录」。
- 用户可以直接向下浏览历史，不强制继续写作。

#### 状态 C：已打卡、今天已有记录

- 打卡卡片保留在页面顶部。
- 显示「今天已记下 N 条」。
- 展示全部历史记录，今天的记录位于最上方。
- 允许继续新增记录。

#### 记忆追踪

- 点击顶部打卡卡片可切换查看记忆追踪，再次点击返回打卡卡片。
- 记忆追踪只展示最近记录日期、累计记录天数、图片数和语音数。
- 记忆追踪不提供页面跳转，不影响打卡与写记录流程。

#### 空间提示内容

- 打卡卡片下方可以展示非阻塞提示，例如人物生日、那年今日、人物回忆和备份提醒。
- 人物生日提示默认只展示未来 3 天内或当天最近的一位人物；点击后进入人物详情。
- 提示内容与用户记录使用不同视觉层级，不改变历史记录排序。

#### 业务规则

- 每个自然日最多生成一条打卡事实。
- 打卡时可经用户授权读取当前位置并保存城市名称；用户也可以不记录城市继续打卡，不保存经纬度。
- 同一天允许创建多条记录。
- 打卡不要求填写内容。
- MVP 不提供补签；用户可为过去日期补写记录，但不生成历史打卡。
- 自然日依据用户设备时区生成 `dayKey`。

### 8.2 写一条

#### 必备字段

| 字段 | 规则 |
|---|---|
| 正文 | 可为空，但正文、图片和语音至少存在一项 |
| 图片 | 0–9 张 |
| 语音 | 0–N 段，在当前光标位置插入，保留原始录音并支持本地播放 |
| 关联人物 | 0–10 人 |
| 地点 | 可为空，可读取当前位置或输入自定义地点文字，不保存经纬度 |
| 记录日期 | 默认当天，可选择过去日期，不可选择未来日期 |

#### 交互要求

- 移动端使用全屏所见即所得编辑器；顶部仅保留返回、状态和保存，正文占据主要空间。
- 正文以 Markdown 保存，编辑区域直接呈现格式化结果，不提供单独的预览切换。
- 支持标题、加粗、斜体、引用、无序列表、有序列表、链接和行内代码。
- 键盘上方固定展示高频操作：图片、`@人物`、语音、加粗和列表；标题、撤销/重做、斜体、引用、链接、分隔线、表格、代码块和其他低频格式放入「更多」。图片支持拍摄或从系统相册选择。
- 所有编辑器操作按钮的触控区域不得小于 44 × 44 pt。
- 自动保存本地草稿，并显示最近保存状态。
- 图片插入当前光标位置，并在所见即所得编辑区域按正文顺序渲染。
- 语音在当前光标位置显示录音状态；完成后成为正文节点，支持播放、进度、移除及重复插入。
- 语音文件默认只保存在本机，编辑草稿、记录详情、空间历史列表和 ZIP 备份均保留语音引用。
- 仅支持 iOS 和 Android；录音、照片选择、本地通知和系统分享均以移动端能力为准。
- 输入 `@` 时打开人物选择；首次使用某个名字时可快速创建人物。
- 保存过程不要求标题、分类或心情标签。
- 退出未保存内容时二次提示。
- 创建后允许编辑和删除。

### 8.3 空间历史记录与日历

- 空间展示全部历史记录，按 `dayKey` 倒序分组，同一天内按创建时间倒序排列。
- 每个日期分组可以同时包含打卡事实和多条记录。
- 打卡事实以弱视觉行展示，不独占大卡片；只有纯打卡日时仍保留日期分组。
- 记录卡片在有限高度内展示预览：正文超出行数后省略，图片保持比例并在最大高度内完整展示，录音显示有限数量的波形和时长；超出部分在详情页查看。
- 点击记录卡片进入详情页，查看完整正文、原图和可播放录音。
- 历史列表使用虚拟化渲染，避免一次性绘制全部历史内容。
- 日历为独立一级入口，展示月历主体、月份切换、农历日期、节气节日、人物生日、记录日期标记和选中日期详情。
- 月历使用类型标记表达打卡、文字、图片、录音和生日；今日使用独立标记，不显示图片缩略图，也不标记缺卡或失败。
- 选中日期展示黄历宜忌，以及当天生日、打卡和日记的轻量列表；地点和媒体摘要随对应条目展示。

MVP 不提供日记全文搜索和复杂内容筛选；人物列表支持按姓名、关系或印象搜索。

### 8.4 人物

#### 创建人物

MVP 只要求人物名称，其余资料均为可选。

| 字段 | 必填 | 说明 |
|---|---:|---|
| 名称 | 是 | 支持重名 |
| 头像 | 否 | 本地媒体 |
| 性别 | 否 | 女、男或其他 |
| 与我的关系 | 否 | 自由文本，如妈妈、朋友、同事 |
| 一句话印象 | 否 | 最多 100 字 |
| 生日 | 否 | 支持公历、农历和闰月，可单独控制提醒及提醒时间 |
| MBTI | 否 | 标准 16 型之一 |
| 人物标签 | 否 | 单条标签可多选，标签组内单选 |

#### 人物记忆页

- 展示人物基本信息。
- 展示生日及自动派生的星座、生肖，并展示 MBTI 和自定义标签。
- 自动聚合所有关联该人物的记录。
- 按日期倒序展示。
- 提供人物相册和加密资料收集入口。
- 人物列表支持按名称、关系或印象搜索，默认按最近关联排序。
- 人物列表显示共同记录数量和最近共同记录日期。
- 支持从人物页新增一条记录，并默认关联该人物。
- 删除人物前说明：人物会被删除，历史记录保留，只解除关联。

#### 标签管理

- 内置 MBTI、星座、生肖和自定义标签体系；星座与生肖由生日自动计算，不手动选择。
- 用户可创建、改名和删除单条标签及标签组；单条标签可多选，标签组内单选。
- 用户可调整标签体系是否启用及展示顺序；删除标签只解除人物关联，不删除人物。

#### 人物与个人相册

- 「我的」和每个人物均可拥有多个本地相册。
- 支持创建、改名、排序和删除相册，以及批量添加、排序、设为封面和移除照片。
- 删除非空相册或人物时需确认；对应相册数据和本地文件随归属对象清理。
- 相册及原始照片包含在 ZIP 备份与恢复中。

#### 加密资料收集

- 用户可从人物详情选择姓名、性别、生日、MBTI 和人物标签，生成 7 天有效的一次性邀请链接。
- 对方在静态门户页面本地填写所选字段；至少填写一项后，浏览器使用一次性密钥生成加密回信链接或备用码。
- App 只接受对应未过期邀请的回信，在本机解密并逐项展示差异；用户明确勾选后才更新人物资料。
- 邀请私钥保存在本机安全存储，邀请过期或成功导入后清理；待处理邀请不进入备份。
- 首版只支持上述短文本资料，不收集头像、关系、印象、日记或相册。

MVP 不实现关系图、任意自定义字段、人物间连线和独立事件模型。

### 8.5 回忆

MVP 只实现两类确定性回忆，不使用 AI：

#### 那年今日

- 匹配往年相同月日的记录。
- 有内容时最多展示一张入口卡片。
- 无内容时不占位、不提示缺失。

#### 人物回忆

- 从已关联人物的历史记录中选择一条。
- 同一条记录 30 天内不重复主动展示。
- 用户可关闭某个人物的回忆展示，但不影响数据保存。

#### 原则

- 回忆是邀请，不是通知轰炸。
- 今日页最多展示一张回忆或备份提醒；两者按优先级轮换，不同时占用主要内容区域。
- 不根据正文推断情绪、健康状态或关系好坏。
- 已删除内容不得出现在回忆中。

#### 通知触发规则

- 回忆通知只使用本机数据安排；默认在 20:00 触发，相邻两次至少间隔 7 天，并根据记录距今时间和已回看次数调整下一次提醒。
- 回忆通知一次最多预排 3 条，关闭后取消尚未触发的本地通知，历史记录和今日页回忆不受影响。
- 生日通知按设备当前时区安排未来 12 个月的事件；每个人物在生日提前 3 天和生日当天各提醒一次，时间由用户设置。
- 通知只包含人物名称、日期和提示语，不包含正文、关系、印象、标签或照片。

### 8.6 数据导出与恢复

#### 导出

- 导出一个 ZIP 文件。
- 包含结构化 JSON、可读 Markdown 和原始媒体。
- manifest 记录数据版本、导出时间和文件校验信息。
- 导出前展示预计大小和保存位置说明。
- 本机存在密码本时，只额外加入原始加密文件 `vault.enc`；结构化 JSON、Markdown、文件名和说明不得包含密码字段或主密码。

#### 恢复

- 支持从本产品导出的 ZIP 恢复。
- 恢复前校验版本和文件完整性。
- MVP 采用整体覆盖恢复，不做增量合并。
- 覆盖前必须明确展示本地现有数据将被替换，并要求二次确认。
- 日记恢复与密码本恢复独立确认；旧备份或不恢复密码本时保留当前密码本。
- 恢复密码本前先验证备份主密码；本机已有密码本时还需验证当前主密码并明确确认替换，生物识别材料不随备份恢复。

#### 自动提醒

- 用户累计产生 7 条记录后，首次提示设置备份习惯。
- 后续仅在距离上次导出超过 30 天且有新增内容时展示非阻塞提醒。

### 8.7 密码本

- 「我的」页面提供密码本入口，不增加一级 Tab。
- 首次创建必须设置并确认至少 6 个字符的独立主密码；主密码不落盘、不可重置，遗忘后只能删除密码本重新创建。
- 条目包含名称、账号、密码、网址和备注，名称与密码必填；所有字段、时间戳和条目数量统一保存在本机认证加密文件中，不进入日记数据库。
- 密码默认遮蔽，只有用户主动操作才显示或复制；复制后 60 秒仅在剪贴板仍是本次密码时尝试清理。
- 可选用系统指纹或面容快捷解锁；系统安全存储只保存受认证保护的本机数据密钥，不保存主密码或条目。
- 离开密码本、应用进入非活跃或后台状态时立即锁定；密码本页面阻止截图录屏并保护任务切换预览。
- 修改主密码必须再次验证当前主密码；删除整个密码本不影响日记、人物和媒体。
- 首版不提供同步、自动填充、浏览器插件、密码生成器、分享、明文导出或主密码恢复后门。

### 8.8 设置

- 个人资料支持头像、昵称、个人简介、个性签名、性别、公历或农历生日、MBTI 和自定义标签。
- 提供苔绿、暖砂、夜墨三套主题，并可分别设置个人名字和朋友名字的展示样式。
- 提供空间回忆、人物生日提醒和回忆通知开关；生日提醒支持通用时间和人物专属时间，通知权限或调度失败时提供处理入口。
- Android 支持可选的常驻快捷栏，展示打卡状态和快捷入口。
- 提供标签管理、系统权限说明、数据导出恢复、本地数据删除、隐私政策和产品信息。
- Android APK 支持启动时自动检查和手动检查更新，下载面板展示进度、速度与剩余时间，并支持暂停后继续、下载源回退和安装权限引导；iOS 只展示当前版本信息。

### 8.9 音乐盒与全局播放器

#### 音乐盒

- 「我的」页面增加「音乐盒」，展示我收藏的音乐曲目。
- 用户可通过系统文件选择器导入本地音频；首批支持 mp3、m4a、aac、wav、flac 和 ogg，实际可播放性以设备解码能力为准。
- 导入文件复制到应用沙盒，不长期依赖外部 URI；默认从文件名生成标题，用户可编辑标题、艺术家和专辑。
- 曲目文件与收藏关系分离；同一曲目可以同时出现在我的音乐盒和多个人物的喜欢列表。
- 曲目支持播放、编辑、删除；删除前显示文件和播放队列影响。
- 音乐盒采用“曲库概览 → 播放操作 → 搜索 → 歌曲列表”的层级，不提供脱离当前播放会话的“打开播放详情”入口。
- 列表顶部提供“播放全部”和“随机播放”；点击歌曲行立即播放，点击更多按钮打开编辑、移出音乐盒和永久删除操作。
- 歌曲行只展示播放状态、标题、艺术家/专辑和更多按钮，不把编辑、删除等低频命令平铺在主列表。

#### 人物喜欢的音乐

- 人物详情增加「喜欢的音乐」模块，可从已有曲库选择曲目或导入新曲目。
- 从人物喜欢列表移除只删除收藏关系，不删除曲目文件或其他收藏。
- 删除人物只删除该人物的喜欢关系，不影响我的音乐盒或其他人物收藏。

#### 播放列表与播放模式

- 播放页可选择聚合来源：我的音乐盒、指定人物的喜欢的音乐或多个来源组合。
- 队列按曲目 ID 去重并保存来源选择；队列变化不打断仍然有效的当前播放。
- 支持列表循环、随机播放和单曲循环。
- 随机模式使用不重复洗牌；当前洗牌周期播放完后重新生成顺序。
- 当前曲目被删除或无法解码时，播放器跳过无效项并显示可理解的错误状态。
- 来源筛选和歌曲列表放在独立的播放队列底部抽屉中；完整播放页不在主滚动区域混排曲库列表。
- 队列抽屉支持切换“全部 / 我的音乐 / 人物喜欢”，点击歌曲立即切歌并保留当前队列来源。

#### 全局悬浮播放器

- 应用根布局维护唯一播放会话，跨页面切换保持当前曲目、队列、播放位置、播放状态和模式。
- 悬浮播放器提供播放/暂停、关闭和进入播放页；关闭只停止并清空播放会话，不删除曲库文件。
- 悬浮播放器提供队列入口；打开队列时进入播放页并直接展开队列抽屉。
- 悬浮播放器整体可在安全显示范围内自由拖动，松手后限制在可见区域并保存位置。
- 进入完整播放页时隐藏悬浮播放器；离开详情页且播放会话仍存在时恢复显示。
- 完整播放页只聚焦当前曲目，提供曲目信息、进度条、播放/暂停、上一首、下一首、当前播放模式和队列入口；返回表示最小化，不停止播放。

### 8.10 我的书架与阅读

> 当前实现边界：EPUB 可重排内核与 PDF 原生固定版式内核已经接入，DOM `<embed>` 不再用于移动端生产阅读。MOBI/AZW/AZW3 仍只归档；双平台大文件、旋转、受保护文件和备份恢复仍需发布前真机签收。

#### 书架管理

- 「我的」页面提供「我的书架」，允许导入 PDF、EPUB、MOBI、AZW 和 AZW3 原始文件。
- 导入前展示文件名称和大小；导入后复制到应用沙盒，原始文件不被重编码或覆盖。
- 用户可编辑书名、作者和封面，可按最近阅读、最近导入或标题排序，并支持搜索和删除。
- 书籍记录包含格式、文件大小、阅读进度和解析状态。
- 解析状态必须明确区分可读、受保护、不支持和解析失败；不可读文件仍保留在书架并显示原因。
- 第一阶段只承诺 EPUB 和 PDF 可阅读。MOBI、AZW、AZW3 只归档和管理，统一标记“当前版本不可阅读”；不破解 DRM，也不做隐式格式转换。

#### 阅读器与进度

- 阅读器采用双内核：EPUB 使用可重排内核，PDF 使用固定版式内核；两者共享控制层、定位协议、摘抄入口和持久化会话，但不强行统一渲染能力。
- 阅读页默认只有正文。系统状态栏始终保留并与阅读主题同色；顶部控制位于安全区下方，底部控制和抽屉避开 Home Indicator/系统导航区。
- 点击正文中部切换控制层；EPUB 左右点击区用于翻页，长按/拖动仍交给文本选区。PDF 的滚动、缩放和文本选择优先，控制层不得用全屏透明层拦截手势。
- 控制态顶部只提供返回、当前章节/书名和更多；底部第一行提供上一章、章节进度、下一章，第二行只保留目录、主题、设置和摘抄。
- 目录使用底部抽屉，包含“目录 / 摘抄 / 笔记”三个页签。目录显示层级和当前章节高亮；关闭后保持原阅读位置。
- EPUB 保存 CFI、章节 href、章节标题和全书 progression；PDF 保存页码，并在内核可可靠返回总页数时保存页数进度。每次稳定位置变化防抖保存，离开和进入后台时立即保存。
- EPUB 显示设置支持字号、行距、页边距、系统衬线/无衬线字体、纸白/暖黄/护眼绿/夜间主题，以及“左右翻页 / 上下滚动”。首版不提供在线字体、自定义背景图、仿真翻页、自动阅读和应用内亮度控制。
- PDF 保留原始排版，只提供主题遮罩、滚动方向、缩放和页码跳转；不得展示无效的字号、行距和章节控制。
- 原始书籍始终保留，解析缓存可删除并重建。

#### 摘抄与读书笔记

- EPUB 支持长按选择正文后执行“摘抄”；保存选中文本、内核可提供的前后文摘要、CFI 范围、章节和创建时间，并以轻量高亮回显。
- PDF 只有在内核可靠返回选区文本和页码时才提供直接摘抄；否则允许在摘抄抽屉手动录入并绑定当前页，界面必须标记“手动摘抄”。
- 摘抄支持查看、编辑备注和删除；书籍详情按时间展示摘抄列表。
- 从摘抄点击「写观后感」时，打开现有 Markdown 编辑器并预填不可变引用块。
- 从书籍详情点击「写读书笔记」时，打开现有 Markdown 编辑器并记录书籍来源。
- 读书笔记作为普通历史记录进入空间时间线，可继续添加图片、语音和人物关联。
- 引用保存书名、摘抄文本和定位快照；原书删除后，摘抄与笔记仍可展示并标记“原书已删除”。

#### 首版主动削减

- 不包含下载、评论、分享、金币、关注、听书、改编剧场等内容平台能力。
- 不包含全文搜索、跨书搜索、云书架、阅读排行、阅读时长激励和社交书评。
- 不把 MOBI/AZW/AZW3“可导入”描述成“可阅读”；后续仅在独立解析兼容性验证通过后开放。
- 不复刻参考产品的品牌、图标、文案、素材和商业入口，只采用正文优先、按需控制、工具抽屉的成熟交互层级。

- `TagDefinition` 保存标签名称、标准化名称和可选标签组；名称全局唯一。
- `TagGroup` 保存自定义单选组；组名全局唯一。
- `PersonTagAssignment` 保存人物与 MBTI 或自定义标签的关联。
- 星座与生肖不单独存储，由生日实时派生。

### 9.12 Album 与照片排序

- `PersonAlbum.personId` 为空时表示个人相册，否则归属于指定人物。
- `AlbumMedia` 保存相册与媒体的一对一归属、排序和加入时间；同一照片不跨相册复用。
- 相册封面引用相册内媒体；删除封面照片后自动选择下一张或清空封面。

### 9.13 ProfileCollectionRequest

- 保存邀请 ID、目标人物、允许填写的字段、临时标签映射、过期时间和处理状态。
- 邀请默认 7 天有效，只允许 `pending` 状态且未过期的请求完成一次导入。
- 请求元数据保存在本地数据库，解密私钥独立保存在本机安全存储；二者不进入 ZIP 备份。

### 9.14 数据删除规则

- 删除 Post 时解除人物关联，并按引用计数清理无引用媒体。
- 删除 Person 时保留 Post 并解除对应关联，同时删除该人物的资料、标签关联、相册和相册媒体。
- 删除相册或从相册移除照片时，同时删除对应的本地相册媒体文件。
- 删除待处理资料邀请或邀请过期时，同时清理对应本机私钥。
- 删除 Book 时删除原始书籍文件、封面和解析缓存，但保留摘抄文本与阅读笔记引用快照。
- 删除 MusicTrack 时从播放队列移除；仅在音频文件无其他有效引用时删除文件。
- 删除全部本地数据必须二次确认，并说明已导出的备份不会被删除。
- 删除整个密码本时清理正式、临时、回滚加密文件和生物识别材料；删除全部本地数据必须同时覆盖密码本。

## 10. 隐私与安全

- 正文、人物现有资料和媒体默认不离开设备；只有用户主动导出或分享资料收集邀请时才发生明确的数据流转。
- 资料收集邀请只携带用户选定的字段类型和可选标签，不携带目标人物现有资料；对方回答在浏览器本地加密，只能由发起邀请的设备解密。
- 不接入第三方行为追踪 SDK。
- 产品分析优先使用不含正文、人物名、图片和精确记录时间的匿名事件。
- 崩溃日志不得包含用户内容、文件路径和导出包内容。
- 本地数据库和媒体应使用系统沙箱；支持平台安全能力时启用静态加密。
- 密码本独立于日记数据库，使用内存困难 KDF、随机 256 位数据密钥和 AES-256-GCM 认证加密；主密码、派生密钥和条目明文不得落盘。
- 密码本不发起网络请求，不接入分析事件；系统分享只允许用户主动导出包含加密 `vault.enc` 的完整 ZIP。
- 本机生物识别只是快捷解锁，不能替代当前主密码验证，也不能作为跨设备恢复手段。
- 删除操作必须真实删除本地记录，不使用不可见的软删除保留用户正文。

## 11. 成功指标

### 11.1 北极星指标

**每周获得一次历史回看价值的活跃用户数。**

定义：一周内至少打开过一条 7 天以前的记录、人物记忆或那年今日内容的用户数。

该指标用于确认产品不仅让用户写入，也能让历史内容产生价值。

### 11.2 MVP 观察指标

| 指标 | 目标 | 目的 |
|---|---:|---|
| 首次打卡完成率 | ≥ 70% | 验证入口是否清晰 |
| 首次打卡后记录转化率 | ≥ 25% | 验证打卡能否承接表达 |
| 新用户 7 日内记录 3 天比例 | ≥ 25% | 验证轻量习惯 |
| 有记录用户的人物关联率 | ≥ 20% | 验证人物价值 |
| 第 4 周历史内容打开率 | ≥ 30% | 验证回看价值 |
| 数据导出成功率 | ≥ 95% | 验证数据可信度 |

指标目标为产品假设，需通过首轮真实用户测试校准，不作为未经验证的行业基准。

### 11.3 不作为核心指标

- 最长连续打卡天数。
- 单日使用时长。
- 单日打开次数。
- 用户创建人物数量。

产品不以延长使用时间或制造断签焦虑为目标。

## 14. 当前已确认决策

本次实现采用以下决策：

1. 当天未打卡前不能写当天记录；允许从历史日期补写，人物页新增当天记录同样遵循该规则。
2. 出生日期为可跳过的本地资料，不展示「已经活了 N 天」，避免制造计数压力。
3. MVP 只支持 iOS/Android，不维护 Web/PWA 和微信小程序客户端；文档、构建和验收均以移动端为准。
4. MVP 完全免账号；同步进入后续阶段后再单独设计账号引导。
5. 删除记录立即生效并二次确认，MVP 不提供撤销和回收站。
6. MVP 支持关闭全局或指定人物的主动回忆，不修改和删除原始记录。
7. 一级入口使用「空间」和「日历」；空间负责创建与连续浏览全部历史，日历负责按月份查看记录分布。
8. 空间中的生日提示只覆盖当天至未来 3 天，并只展示最近的一位人物。
9. 门户是静态产品、下载和资料收集页面，不是承载日记数据的 Web 客户端；资料回信只提供加密传递，不在门户保存人物资料。

## 15. V3 相对现有方案的关键调整

- 从「功能完整」改为「闭环优先」。
- 移除公共故事社区和死亡确认。
- 暂缓人物关系图、独立事件系统和高级备份协议。
- 把人物设计成记录的轻量关联对象，而不是先维护完整档案。
- 把回看明确为核心能力和北极星指标。
- 不用连续打卡和断签损失制造留存。
- 首次使用不强制账号，先让用户获得记录价值。
- 用可读导出建立数据信任，而不是只强调技术上的本地优先。
