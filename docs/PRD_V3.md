# 产品需求文档 V3 — 仍在 / Still Alive

> 每天留下一点，慢慢得到一份属于自己的生命档案。

| 项目 | 内容 |
|---|---|
| 文档状态 | MVP P0 已实现，待真机验收 |
| 产品阶段 | MVP |
| 核心定位 | 本地优先的个人生命记录工具 |
| 核心闭环 | 打卡 → Markdown 日记 → 图片/人物关联 → 时间沉淀 → 回看 |

---

## 1. 产品结论

「仍在」不是连续打卡挑战，也不是要求用户每天认真写作的日记应用。

它通过一次低成本的每日确认，帮助用户逐渐留下生活片段，并按时间与人物自动组织。随着记录累积，产品最终形成一份可回看、可迁移、属于用户自己的生命档案。

产品的长期价值不来自连续天数，而来自三件事：

1. 让记录足够容易开始。
2. 让零散内容自动形成时间和人物脉络。
3. 让过去的记录在合适的时间重新出现。

## 2. 问题与机会

### 2.1 用户问题

- 传统日记的写作门槛高，用户很难长期坚持。
- 相册记录了画面，但缺少当时的感受、人物和背景。
- 笔记工具擅长保存内容，但不擅长形成个人生命脉络。
- 重要人物的共同经历散落在聊天、照片和记忆中，难以回看。
- 私密记录放在第三方平台时，用户担心泄露、停服和无法迁移。

### 2.2 产品机会

用「打卡」降低每天打开产品的成本，用「写一条」承接偶发的表达欲，再通过人物关联和回忆触发，让内容随时间产生复利。

## 3. 产品目标

### 3.1 MVP 目标

- 用户能在 5 秒内完成当天打卡。
- 用户打卡后能自然地写下一条可选记录。
- 用户能用适合移动端的全屏 Markdown 编辑器记录文字和图片。
- 用户能把记录关联到一个或多个人物。
- 用户能按时间和人物回看历史内容。
- 用户能完整导出自己的数据和媒体文件。
- 用户中断使用后能够无压力地重新开始。

### 3.2 非目标

MVP 不包含：

- 公共故事社区、关注、评论、私信等社交功能。
- 排行榜、积分、断签惩罚等游戏化机制。
- 人物之间的复杂关系图编辑。
- WebDAV、S3 等高级云同步配置。
- 多设备实时双向同步和冲突合并。
- AI 自动总结、心理分析或人物关系判断。
- 未打卡后向紧急联系人发送生存或死亡确认。

## 4. 目标用户

### 4.1 核心用户

- 想记录生活，但无法坚持写长日记的人。
- 希望长期保存孩子、伴侣、父母或朋友共同经历的人。
- 正处于毕业、迁居、恋爱、育儿、照护等人生阶段的人。
- 重视隐私、数据所有权和长期可迁移性的人。

### 4.2 不优先服务的用户

- 主要诉求是公开表达和获得互动反馈的用户。
- 需要团队知识管理或专业笔记编辑能力的用户。
- 只关心习惯追踪、目标管理和效率统计的用户。

## 5. 核心原则

### 5.1 记录没有负担

- 打卡一次点击即可完成。
- 写作永远可选。
- 不设置最低字数。
- 不因断签制造损失感、羞耻感或焦虑。

### 5.2 历史内容必须重新产生价值

产品不能只负责保存。它需要通过「那年今日」、人物回忆和阶段回顾，让用户重新遇见过去的内容。

### 5.3 人物关联优于人物维护

用户主要在写记录时顺手关联人物。人物档案由历史记录逐渐形成，不要求用户预先填写大量资料。

### 5.4 数据默认属于用户

- 私密内容默认保存在本地设备。
- 数据可完整导出，格式有文档说明且不依赖本产品才能读取。
- MVP 不以无法迁移的数据锁定用户。

### 5.5 文案温和、明确

- 不使用「必须」「立即」「失败」「断签」「失联」「死亡确认」等施压词汇。
- 用户中断后返回，默认文案为「今天也可以重新开始」。
- 连续天数是信息，不是评价。

## 6. 核心用户旅程

### 6.1 第一次使用

1. 用户进入产品，看到一句定位说明和本地存储说明。
2. 用户选择是否设置昵称和出生日期；均可跳过。
3. 用户进入今日页。
4. 页面只突出一个主要动作：「今天也在」。
5. 完成后出现可选动作：「想留下一点什么吗？」

首次使用不强制注册、不强制创建人物、不强制配置备份。

### 6.2 日常使用

1. 打开今日页。
2. 点击「今天也在」。
3. 可直接离开，也可写下一条记录。
4. 写记录时可添加图片、关联人物。
5. 保存后回到时间线，看到今天的内容已经沉淀。

### 6.3 回看

1. 首页在存在历史内容时展示一条回忆入口。
2. 用户可查看「那年今日」或与某个人相关的过去记录。
3. 用户可以补充当时的背景，但不修改原始创建时间。

### 6.4 中断后返回

1. 不弹出断签警告。
2. 不要求补签。
3. 显示「欢迎回来，今天也可以重新开始」。
4. 用户完成当天打卡后恢复正常流程。

## 7. 信息架构

MVP 使用四个一级入口：

| 入口 | 作用 |
|---|---|
| 今日 | 打卡、可选记录、轻量回忆入口 |
| 时间 | 时间线、日历、历史回看 |
| 人物 | 人物列表及人物记忆页 |
| 我的 | 数据导出、恢复、偏好和产品说明 |

「写一条」不是一级导航。它只在完成当天打卡后出现，也可以从某个历史日期或人物页进入。四个一级入口保持稳定，不增加独立编辑器 Tab。

## 8. 功能需求

### 8.1 今日状态

今日页有三个状态。

#### 状态 A：今天未打卡

- 显示当前日期。
- 显示累计记录天数；首次使用时显示产品引导。
- 主要按钮：「今天也在」。
- 不展示连续天数压力文案。
- 不展示写作输入框。

#### 状态 B：已打卡、今天未记录

- 显示「今天已留下一个小小的坐标」。
- 次要按钮：「想留下一点什么吗？」
- 提供「先这样」退出路径。

#### 状态 C：已打卡、今天已有记录

- 折叠打卡卡片。
- 显示「今天已记下 N 条」。
- 展示今天的记录列表。
- 允许继续新增记录。

#### 业务规则

- 每个自然日最多生成一条打卡事实。
- 同一天允许创建多条记录。
- 打卡不要求填写内容。
- MVP 不提供补签；用户可为过去日期补写记录，但不生成历史打卡。
- 自然日依据用户设备时区生成 `dayKey`。

### 8.2 写一条

#### 必备字段

| 字段 | 规则 |
|---|---|
| 正文 | 可为空，但正文和图片至少存在一项 |
| 图片 | 0–9 张 |
| 关联人物 | 0–10 人 |
| 记录日期 | 默认当天，可选择过去日期，不可选择未来日期 |

#### 交互要求

- 移动端使用全屏编辑器；顶部仅保留返回、预览和保存，正文占据主要空间。
- 正文以 Markdown 保存，支持编写/富文本预览切换。
- 支持标题、加粗、斜体、引用、无序列表、有序列表、链接和行内代码。
- 键盘上方固定展示高频操作：图片、`@人物`、标题、加粗、列表和更多；低频格式放入「更多」。
- 所有编辑器操作按钮的触控区域不得小于 44 × 44 pt。
- 自动保存本地草稿，并显示最近保存状态。
- 图片插入当前光标位置；预览时按正文顺序渲染。
- 输入 `@` 时打开人物选择；首次使用某个名字时可快速创建人物。
- 保存过程不要求标题、分类或心情标签。
- 退出未保存内容时二次提示。
- 创建后允许编辑和删除。

### 8.3 时间线

- 按记录日期倒序展示。
- 打卡事实以弱视觉标识呈现，不独占大卡片。
- 同一天的多条记录归入同一日期分组。
- 支持按月份快速定位。
- 支持在时间线/月历之间切换，并从月历选择日期。
- 没有正文的纯打卡日仍可在日历中显示。
- 月历只表达记录密度：纯打卡日显示小圆点，有日记显示实心圆，有图片可显示微型缩略图；不标记缺卡或失败。

MVP 不提供全文搜索、复杂筛选和标签系统。

### 8.4 人物

#### 创建人物

MVP 只要求人物名称，头像和关系均为可选。

| 字段 | 必填 | 说明 |
|---|---:|---|
| 名称 | 是 | 支持重名 |
| 头像 | 否 | 本地媒体 |
| 与我的关系 | 否 | 自由文本，如妈妈、朋友、同事 |
| 一句话印象 | 否 | 最多 100 字 |

#### 人物记忆页

- 展示人物基本信息。
- 自动聚合所有关联该人物的记录。
- 按日期倒序展示。
- 支持从人物页新增一条记录，并默认关联该人物。
- 删除人物前说明：人物会被删除，历史记录保留，只解除关联。

MVP 不实现关系图、自定义字段、人物间连线和独立事件模型。

### 8.5 回忆

MVP 只实现两类确定性回忆，不使用 AI：

#### 那年今日

- 匹配往年相同月日的记录。
- 有内容时最多展示一张入口卡片。
- 无内容时不占位、不提示缺失。

#### 人物回忆

- 从已关联人物的历史记录中选择一条。
- 同一条记录 30 天内不重复主动展示。
- 用户可关闭某个人物的回忆展示，但不影响数据保存。

#### 原则

- 回忆是邀请，不是通知轰炸。
- 不根据正文推断情绪、健康状态或关系好坏。
- 已删除内容不得出现在回忆中。

### 8.6 数据导出与恢复

#### 导出

- 导出一个 ZIP 文件。
- 包含结构化 JSON、可读 Markdown 和原始媒体。
- manifest 记录数据版本、导出时间和文件校验信息。
- 导出前展示预计大小和保存位置说明。

#### 恢复

- 支持从本产品导出的 ZIP 恢复。
- 恢复前校验版本和文件完整性。
- MVP 采用整体覆盖恢复，不做增量合并。
- 覆盖前必须明确展示本地现有数据将被替换，并要求二次确认。

#### 自动提醒

- 用户累计产生 7 条记录后，首次提示设置备份习惯。
- 后续仅在距离上次导出超过 30 天且有新增内容时展示非阻塞提醒。

### 8.7 设置

- 昵称和出生日期。
- 浅色、深色或跟随系统。
- 每日温和提醒；默认关闭。
- 回忆展示开关。
- 数据导出、恢复和本地数据删除。
- 隐私说明和数据存储位置说明。

## 9. 数据模型

### 9.1 Checkin

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 本地唯一 ID |
| dayKey | string | `YYYY-MM-DD`，按设备时区生成 |
| createdAt | datetime | 实际创建时间 |

约束：`dayKey` 唯一。

### 9.2 Post

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 本地唯一 ID |
| dayKey | string | 内容所属日期 |
| body | string | 正文，可为空 |
| format | `markdown` | MVP 固定为 Markdown |
| mediaIds | string[] | 图片引用 |
| personIds | string[] | 关联人物 |
| createdAt | datetime | 创建时间，不因修改改变 |
| updatedAt | datetime | 最后修改时间 |

### 9.3 Person

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 本地唯一 ID |
| name | string | 人物名称 |
| avatarMediaId | string? | 头像引用 |
| relationToMe | string? | 与我的关系 |
| impression | string? | 一句话印象 |
| memoryEnabled | boolean | 是否允许主动展示人物回忆 |
| createdAt | datetime | 创建时间 |
| updatedAt | datetime | 修改时间 |

### 9.4 Media

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 本地唯一 ID |
| localPath | string | 本地文件引用 |
| mimeType | string | 文件类型 |
| width | number? | 图片宽度 |
| height | number? | 图片高度 |
| checksum | string | 完整性校验 |
| createdAt | datetime | 创建时间 |

### 9.5 数据删除规则

- 删除 Post 时解除人物关联，并按引用计数清理无引用媒体。
- 删除 Person 时保留 Post，仅删除对应 `personIds` 引用。
- 删除全部本地数据必须二次确认，并说明已导出的备份不会被删除。

## 10. 隐私与安全

- 未经用户主动导出或未来明确启用同步，正文、人物和媒体不得离开设备。
- 不接入第三方行为追踪 SDK。
- 产品分析优先使用不含正文、人物名、图片和精确记录时间的匿名事件。
- 崩溃日志不得包含用户内容、文件路径和导出包内容。
- 本地数据库和媒体应使用系统沙箱；支持平台安全能力时启用静态加密。
- 删除操作必须真实删除本地记录，不使用不可见的软删除保留用户正文。

## 11. 成功指标

### 11.1 北极星指标

**每周获得一次历史回看价值的活跃用户数。**

定义：一周内至少打开过一条 7 天以前的记录、人物记忆或那年今日内容的用户数。

该指标用于确认产品不仅让用户写入，也能让历史内容产生价值。

### 11.2 MVP 观察指标

| 指标 | 目标 | 目的 |
|---|---:|---|
| 首次打卡完成率 | ≥ 70% | 验证入口是否清晰 |
| 首次打卡后记录转化率 | ≥ 25% | 验证打卡能否承接表达 |
| 新用户 7 日内记录 3 天比例 | ≥ 25% | 验证轻量习惯 |
| 有记录用户的人物关联率 | ≥ 20% | 验证人物价值 |
| 第 4 周历史内容打开率 | ≥ 30% | 验证回看价值 |
| 数据导出成功率 | ≥ 95% | 验证数据可信度 |

指标目标为产品假设，需通过首轮真实用户测试校准，不作为未经验证的行业基准。

### 11.3 不作为核心指标

- 最长连续打卡天数。
- 单日使用时长。
- 单日打开次数。
- 用户创建人物数量。

产品不以延长使用时间或制造断签焦虑为目标。

## 12. MVP 范围与阶段

### 12.1 P0：核心闭环

- 本地数据初始化。
- 今日三态打卡。
- 移动端全屏 Markdown 编辑、富文本预览和本地草稿。
- 创建、编辑、删除记录。
- 图片和人物关联。
- 时间线与日历。
- 人物列表和人物记忆页。
- 那年今日和人物回忆。
- ZIP 导出与整体恢复。

### 12.2 P1：体验增强

- 系统级每日提醒。
- 月度或年度回顾。
- 本地全文搜索。
- 更多媒体类型。
- 备份包加密保护。

### 12.3 P2：长期能力

- 用户自选网盘备份。
- 多设备同步。
- 人物关系图。
- 独立 Event 模型和模糊时间。
- Web、App、小程序之间的数据迁移体验。

## 13. MVP 验收标准

- [x] 新用户不注册也能进入今日页并完成打卡。
- [x] 未打卡状态下不可进入写一条流程。
- [x] 打卡后可以不写内容直接离开。
- [x] 同一天只能生成一次打卡，但可以保存多条记录。
- [x] 日记使用移动端全屏编辑器，支持 Markdown 工具栏和富文本预览。
- [x] 草稿自动保存在本地，异常退出后可以继续编辑。
- [x] 记录支持正文、0–9 张图片和 0–10 个人物关联。
- [x] 图片可以插入正文当前位置，`@` 可以选择或快速创建人物。
- [x] 过去日期可以补写记录，但不会生成补签记录。
- [x] 时间线和日历能够正确展示纯打卡日及有内容日期。
- [x] 删除人物不会删除历史记录，只解除关联。
- [x] 有匹配内容时可展示那年今日和人物回忆。
- [x] 用户可以关闭指定人物的主动回忆展示。
- [x] 导出的 ZIP 同时包含 JSON、Markdown 和原始媒体。
- [x] 导出包能够在全新本地数据环境中完整恢复。
- [x] 断签后返回不显示惩罚、损失或失败文案。
- [x] 未经主动导出，用户正文、人物和媒体不会离开设备。

以上条目已完成代码与静态构建验收；相册、文件选择、系统分享、返回手势及恢复后的媒体显示仍需在 iOS/Android 真机上完成最终交互验收。

## 14. MVP 已确认决策

本次实现采用以下决策：

1. 当天未打卡前不能写当天记录；允许从历史日期补写，人物页新增当天记录同样遵循该规则。
2. 出生日期为可跳过的本地资料，不展示「已经活了 N 天」，避免制造计数压力。
3. MVP 首发目标为 iOS/Android，不维护 Web/PWA 和微信小程序客户端。
4. MVP 完全免账号；同步进入后续阶段后再单独设计账号引导。
5. 删除记录立即生效并二次确认，MVP 不提供撤销和回收站。
6. MVP 支持关闭全局或指定人物的主动回忆，不修改和删除原始记录。

## 15. V3 相对现有方案的关键调整

- 从「功能完整」改为「闭环优先」。
- 移除公共故事社区和死亡确认。
- 暂缓人物关系图、独立事件系统和高级备份协议。
- 把人物设计成记录的轻量关联对象，而不是先维护完整档案。
