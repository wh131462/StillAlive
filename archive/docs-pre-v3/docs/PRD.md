# 产品需求文档 (PRD) - 还活着 / Still Alive

> "你已经活了 N 天。"——一款本地优先的个人编年史工具。
>
> 本次重构：humane-redesign（openspec/changes/humane-redesign/），基于 chronicle-pivot 的本地优先编年史定位，按 Apple Human Interface 原则重新组织主页心流、人物图谱与备份语言。

---

## 1. 产品概述

### 1.1 产品定位

"还活着"是一款**本地优先的个人编年史工具**。它通过分阶段的每日心流（打卡 → 写一条 → 折叠回看）+ 以"我"为中心的人物关系图 + 自由格式的事件经历流，帮助用户记录每一天的存在，并把生命中重要的人沉淀为可回看的关系档案。

所有数据**默认存在你自己的设备上**。可以导出为 .zip 或 .json，也可以同步到你自己的网盘（如坚果云、Nextcloud）作为二级备份。我们不存你的数据。

| 维度 | 说明 |
|------|------|
| 核心驱动 | "活着"的日常感知 + "记录"的主动构建 + "回看"的长期价值 |
| 工具定位 | 本地优先编年史工具，支持"什么都不写只打卡"的轻量模式 |
| 心流 | 打卡 → 想写点什么吗？ → 写完折叠（不强求） |
| 关系沉淀 | 以"我"为中心的关系图 + 人物事件流（自动 + 手动） |
| 数据自主 | 本地存储为主，导出 / 导入为主推，云同步为可选辅路径 |

### 1.2 目标用户

- 希望养成每日反思 / 写作习惯的用户
- 想要长期记录生活、按时间线回看的用户
- 想为身边重要的人建立私人档案（含模糊时间事件）的用户
- 关注数据所有权、不愿意把日记交给第三方云的用户

### 1.3 核心价值观

| 价值观 | 说明 |
|--------|------|
| 顺序流，不并列 | 打卡是写入的前提；先确认存在，再考虑表达 |
| 正向引导 | 所有反馈文案温和、非压力式；按钮文案不出现"立即/必须/确认" |
| 写作即记忆 | 写下来本身就是加深记忆的过程 |
| 关系沉淀 | 关系图 + 事件流，把重要的人从记忆变成可检索的档案 |
| 本地优先 数据自主 | 数据默认只在你设备上，备份由你自选目标 |
| 术语隐藏 | 用户面前不出现 WebDAV / S3 / Markdown / IndexedDB 等专业词 |

### 1.4 核心叙事

产品围绕**"记录你正在活着"**展开，强调累积型的生命叙事。日常心流为三阶段：

| 阶段 | 主区域 | 用户行为 |
|------|--------|----------|
| 状态 A 未打卡 | 「今日打卡」大卡片 + 「✓ 打卡」按钮 | 点一下打卡 |
| 状态 B 已打卡未写 | 卡片变形为「打卡完成 想写点什么吗？」+ 次级 CTA | 可选地打开写一条 sheet |
| 状态 C 已打卡已写 | 卡片折叠为小条「今天已记下 N 条」 | 历史合流接管页面 |

写入永远是**可选**的；打卡是**前提**。

### 1.5 多端形态

| 端 | 技术栈 | 功能定位 |
|----|--------|---------|
| iOS / Android | React Native | 全功能；底部 sheet 写入；关系图为人物 tab 默认视图 |
| Web 桌面 | React (SPA) | **桌面写作 / 阅读视图**：大屏 dashboard、长写作浮层、桌面版关系图 |
| 微信小程序 | Taro (React) | 仅核心：打卡 + 短帖 + 时间线浏览 |

三端共享一份本地数据契约（schema 通过备份包跨设备移植）；UI 组件各端自行实现。

## 3. 功能模块

### 3.1 账户模块

#### 3.1.1 登录

| 项 | 说明 |
|----|------|
| 入口 | 启动 App 未登录时；Web 端通过 nav-rail 「登录」入口 |
| 方式 | 手机号 + 验证码 / 邮箱 + 密码 / 第三方 OAuth |
| 服务器侧 | 仅做账号鉴权与可选备份中转；不存用户记录内容 |

#### 3.1.2 注册

| 项 | 说明 |
|----|------|
| 必填 | 手机号 / 邮箱 + 密码（≥6 位） |
| 可选 | 昵称（用于提醒邮件模板渲染） |
| 自动生成 | `deviceId`（用于备份命名 / 跨设备区分） |

#### 3.1.3 忘记密码

邮箱重置链接 / 短信验证码二选一。

### 3.2 主页模块（home-flow 三态状态机）

主页是一个分阶段顺序流，**不是并列的功能集合**。

#### 3.2.1 顶部固定区

- 日期 mono 字（"5 月 9 日 周六"）
- 「你已经活了」+ 巨字「127 天」（sans 800，72px 主色强调）
- 右上头像 → 跳「我的」

#### 3.2.2 打卡卡片三态

**状态 A 未打卡**

```
┌─────────────────────────┐
│      今日打卡           │
│   先打个卡，再聊点什么   │
│   ┌──────────────┐      │
│   │  ✓ 打卡       │      │
│   └──────────────┘      │
└─────────────────────────┘
```

- 大卡片，gradient 背景（vital-green-soft → white）
- 仅一个主 CTA「✓ 打卡」
- **不显示任何写入入口**

**状态 B 已打卡未写**

```
┌────────────────────────────────┐
│  ✓  今天的存在已记下            │
│     想写点什么吗？   [ 写一条 ] │
└────────────────────────────────┘
```

- 卡片高度变形（弹簧曲线 `cubic-bezier(0.34, 1.56, 0.64, 1)`，380ms）
- 左侧绿色 ✓ 图标 + 右侧次级 CTA「写一条」（描边按钮，非主色填充）
- 点 CTA → 唤起底部 Post Composer sheet

**状态 C 已打卡已写**

```
┌────────────────────────────────┐
│  ✓  今天已记下 N 条    再写一条 │
└────────────────────────────────┘
```

- 折叠为更紧凑的小条
- 右侧不显眼的「再写一条」入口

#### 3.2.3 历史合流

打卡卡片下方是反向时序的「历史合流」滚动区。来源三类：

1. 用户写过的 Post（`.timeline-row` 卡片样式）
2. 过期未补写的 Reminder（`.reminder-badge`「那天是 X 日子」）
3. 空打卡的「我还在」徽章（仅打卡未写帖的日子）

日期分隔条 sticky；距今 7 天内用"昨天 / 前天"相对表述，更远用"X 月 Y 日"。

历史区**任何条目都不附加"在此处写一条"按钮**——唯一的写入入口是打卡卡片的次级 CTA。

#### 3.2.4 Post Composer（底部 sheet）

不再是独立屏，而是底部上拉 sheet。

```
┌─────────────────────────────────┐
│  ─                              │
│  记一条                    ✕   │
├─────────────────────────────────┤
│                                 │
│   [今天发生了什么？也可以什么 │
│    都不写]                     │
│                                 │
├─────────────────────────────────┤
│  @    📷   ⏰              ✓ │
└─────────────────────────────────┘
```

- sheet 从屏底上滑到 75%（移动端）/ 居中浮层（桌面端）
- 顶部 drag handle + 「记一条」+ 关闭按钮
- 中部无边框 textarea，placeholder 温和
- 底部 4 个圆形小图标：@ / 📷 / ⏰ / ✓
- **不显示**「Markdown / 保存草稿 / 自动保存于」字眼
- 点 @ → 上拉二级 sheet 选人物

### 3.3 记录模块

#### 3.3.1 时间线（合并入主页历史合流）

时间线**不再是独立 tab**——它就是主页打卡卡片下方的历史合流。如果用户想看完整时间线，只需向下滚动。

#### 3.3.2 日历（tab 2）

月视图，状态：已打卡 / 已写帖 / 补签 / 今天 / 未来 / 空。点击单日 → 跳到时间线（主页）当日锚点。

#### 3.3.3 Post 数据模型

```ts
type Post = {
  id: string;
  createdAt: string;
  dayKey: string;         // YYYY-MM-DD
  body: string;           // markdown
  photos: { path: string; width: int; height: int }[];
  mentions: string[];     // personId
  reminderId: string | null;
  linkedEventId: string | null;  // 若被记为某人经历则关联到 Event
  updatedAt: string;
};
```

#### 3.3.4 @ 提及

@ 是**纯本地索引**。任意 @ 操作**不**产生网络请求、**不**通知对方。

- 输入 `@` → 浮出极简候选 sheet
- 候选优先级：最近 @ 过的人 > 别名匹配 > 名字模糊匹配
- 首次使用 @ 时显示一次性 toast 解释，之后不再出现

#### 3.3.5 Post → Event 选择性关联

当 Post 含 @ 提及时，保存后系统弹一次性 toast「要把这条同时记为 妈妈 的经历吗？」

- 用户点「记一条」→ 自动创建 Event，`linkedPostId` 指向该 Post，`participants = ['self', ...mentions]`
- 用户关闭 toast → 不创建 Event
- 该 toast 可在「设置」中关闭

### 3.4 人物模块

#### 3.4.1 人物关系图（默认视图）

进入「人物」tab → 默认看到关系图，不是列表。

```
                  ┌──────┐
                  │ 妈妈 │ ──── 伴侣 ──── ┌──────┐
                  └──┬───┘                │ 爸爸 │
                     │                    └──┬───┘
                  妈妈│                      │爸爸
                     │                      │
                  ┌──▼──────────────────────▼──┐
                  │           ●  我             │
                  └──┬──────────────────────┬──┘
                     │朋友                  │
                  ┌──▼───┐              ┌───▼──┐
                  │ 小林 │              │ 楠楠 │（孤立 / 尚无共现）
                  └──────┘              └──────┘
```

- 「我」固定在画布中心（vital-green 主色，64px）
- 其他人物围绕"我"散布（同心圆 / 用户拖动后记位置）
- 关系类型标在连线中点（"妈妈"/"朋友"等小 mono 字）
- 拖动单节点 0.4s 长按后跟手移动
- 双指捏合缩放 0.5x~2.5x，以"我"为锚
- 点节点 → 跳人物详情 v2
- 点"我"节点 → 跳「我的」tab

#### 3.4.2 人物列表（副视图）

顶部 `.segmented` 切换到列表。沿用 chronicle-pivot 的人物列表样式。

#### 3.4.3 人物详情 v2

三段式：

**顶部 bio-card**

- 大头像（80px）+ 姓名（24pt sans bold）+ 一行印象短语 + 主题色横条 + 右上「编辑」

**中部 结构化字段 + 自定义字段**

两列 kv-grid：

| 固定字段 | 自定义字段（示例） |
|---------|------------------|
| 性别 | 外号: 慢吞吞 |
| 生日 | 喜欢: 拿铁 |
| MBTI | 怕: 雷雨 |
| 星座 | （+ 添加自定义） |
| 属性 |  |

自定义字段：用户输入键（最长 8 字）+ 值（最长 24 字），无类型约束。

**下部 人生经历事件流**

按 `sortKey` 倒序展示该人物所有相关 `Event`。每条事件显示：

- 标题（大）
- 描述（可折叠 2 行）
- `timeHint`（mono 灰，自由文本）
- 参与者头像串

只有 ta 参与而我未参与的事件（如「妈妈年轻时去过西藏」）显示 「 仅 ta」标记。

末尾「+ 写一条经历」→ 触发 event-composer sheet。

#### 3.4.4 关系类型

预设 + 完全自定义。

**家人预设**：爸爸 / 妈妈 / 儿子 / 女儿 / 兄弟 / 姐妹 / 伴侣 / 爷爷 / 奶奶 / 外公 / 外婆 / 叔叔 / 姑姑 / 舅舅 / 阿姨

**社会预设**：朋友 / 同学 / 老师 / 同事 / 邻居 / 室友 / 恋人 / 前任

**自定义**：用户自由输入（最长 8 字），加入本地词典持续可用。

#### 3.4.5 Event 实体

```ts
type Event = {
  id: string;
  title: string;
  description: string;
  participants: ('self' | string)[];    // 'self' 表示「我」也是参与者
  timeHint: string;                      // 自由字符串："高三那年" / "2018-06" 等
  sortKey: number;                       // 用户拖拽排序权重
  linkedPostId: string | null;
  createdAt: string;
  updatedAt: string;
};
```

#### 3.4.6 事件归属规则

由 `participants` 决定可见性：

- 包含 `'self'` → 出现在我的主页历史合流 + 该人物事件流
- **不**包含 `'self'`（如妈妈年轻时的事）→ **仅**出现在该人物事件流，不出现在我的主页

这条规则让用户可以为人物记录"非我参与的经历"而不污染自己的时间线。

#### 3.4.7 模糊时间

`timeHint` 是自由字符串：

- "高三那年" ✓
- "2018-06" ✓
- "2018 暑假" ✓
- "童年" ✓
- "上个月" ✓

无校验。`sortKey` 由用户拖拽产生，与真实日期解耦。

#### 3.4.8 交集视图（独立入口）

沿用 chronicle-pivot 的 Git branch 风可视化：每人一条横向轴，多 @ 帖处画连接线。位于人物 tab 的二级入口。

### 3.5 提醒模块（Reminder）

独立于 Post 的事件日期提醒。

#### 3.5.1 字段

```ts
type Reminder = {
  id: string;
  title: string;
  targetDate: string;        // YYYY-MM-DD
  recurrence: 'once' | 'yearly' | 'monthly';
  relatedPersonIds: string[];
  note: string | null;
  createdAt: string;
};
```

#### 3.5.2 行为

- 到期当天：主页历史合流顶部 + 日历当日标记
- 过期未补写：主页历史合流相应日期位置显示「那天是 X 日子」徽章
- 徽章 1 点跳 Post Composer sheet，预填标题、关联 reminderId

### 3.6 我的模块

#### 3.6.1 个人信息

头像 / 昵称 / 邮箱 / 已活天数 / 总记录数 / 档案中人物数。

#### 3.6.2 入口

时间线（主页内嵌不重复入口）/ 交集 / 提醒邮件 / 里程碑 / 备份 / 偏好设置。

#### 3.6.3 数据统计

生存天数 / 人物数 / 记录数 三宫格。年度像素图（53 周 × 7 行 heatmap）。

#### 3.6.4 提醒邮件

命名禁用「死亡 / 诅咒 / 已故」；用「提醒邮件」「长时间无记录」「温柔提醒」。

两种模式互斥：

| 模式 | 行为 |
|------|------|
| 邮件提醒 | 触发时向紧急联系人发预设邮件 |
| 仅系统提示 | 触发时仅本地通知，无网络请求 |

触发：连续 N 天无活动；N ∈ {3, 7, 14, 30, 自定义 ≥3 ≤365}，默认 7。

#### 3.6.5 备份（去技术化）

**主推路径：导出 / 导入**

```
┌─────────────────────────────────┐
│      [ 导出全部数据 ]            │
│  会生成一个 .zip 文件，包含你的全 │
│  部日记、人物、提醒              │
│                                 │
│      [ 从备份导入 ]              │
│  从之前导出的文件恢复数据        │
│  （会覆盖现在的内容）            │
└─────────────────────────────────┘

也可以同步到云端 →
```

点击「导出」→ sheet 选格式：

- 「便于阅读的文件包（.zip）」（推荐）
- 「完整数据库文件（.json）」

**云同步路径（默认折叠）：**

点开「也可以同步到云端 →」后展示：

- 网盘服务（下拉：坚果云 / Nextcloud / 自建网盘）
- 网盘地址
- 账号
- 密码（小字「建议用应用专用密码」）
- 文件夹路径
- 「上传前加密保护」toggle（小字「打开后，文件需要密码才能打开，请记好密码」）

UI 中**绝不**出现：WebDAV / S3 / endpoint / region / accessKeyId / secretAccessKey / AES-256-GCM / PBKDF2 / iv / salt。

**测试连接友好**：成功显示「✓ 可以连接」；失败时显示「地址写错了？」「账号或密码不对？」「网络不通？」三种猜测，不直接抛 HTTP 状态码。

**备份文件名**：「还活着 2026-05-13 09-41.zip」（中文 + 时间）。

#### 3.6.6 其他设置

外观（浅 / 深 / 系统）/ 打卡提醒时间 / 通知开关组 / 关于 / 退出登录。

## 4. 业务规则

### 4.1 打卡规则

| 规则 | 说明 |
|------|------|
| 顺序流 | 打卡是写入的前提；未打卡状态下写入入口不可见 |
| 一日一打卡 | 同一 dayKey 多次点击「✓ 打卡」幂等 |
| 写帖即打卡 | 当日有任一 Post 自动视为已打卡 |
| 补签 | 用户可对历史空白日补签 |
| 连续天数 | 任一活动（打卡或 Post）即维持连续 |

### 4.2 Post 多帖规则

| 规则 | 说明 |
|------|------|
| 一日多帖 | 同一 dayKey 允许多条 Post，按 createdAt 倒序 |
| 空帖即打卡 | 仅打卡未写帖时无 Post，但 dayKey 标记存在 |

### 4.3 @ 提及规则

| 规则 | 说明 |
|------|------|
| 纯本地索引 | @ 仅在自己设备上的人物页 / 交集视图可见 |
| 不推送 | 任何 @ 操作都不产生网络请求、不通知对方 |
| 别名匹配 | 自动补全考虑 Person.aliases |
| 候选优先级 | 最近 @ > 别名 > 名字模糊匹配 |
| 首次提示 | 第一次使用 @ 时一次性 toast，之后不再出现 |

### 4.4 提醒规则

| 规则 | 说明 |
|------|------|
| 到期触发 | targetDate 当天主页 + 日历当日标记 |
| 过期沉淀 | 过期未补写则在历史合流显示「那天是 X 日子」徽章 |
| 重复提醒 | yearly / monthly 每次到期独立触发 |
| 转化为 Post | 过期徽章可 1 点变成 Post（携带 reminderId） |

### 4.5 关系类型规则

| 规则 | 说明 |
|------|------|
| 预设 + 自定义 | 预设 25+ 种常见关系（家人 + 社会）+ 用户自由输入 |
| 长度上限 | 自定义关系最长 8 字（保证关系图标签视觉一致） |
| 本地词典 | 自定义类型加入本地词典持续可用 |
| 双向冗余 | 添加 A → B 关系时同时记录 B → A 关系（type 可为 null） |

### 4.6 事件归属规则

| 规则 | 说明 |
|------|------|
| participants 决定可见性 | 包含 self → 主页 + 人物页；不含 self → 仅人物页 |
| timeHint 自由 | 不做日期格式校验 |
| sortKey 用户控制 | 拖拽产生排序权重，与真实日期解耦 |
| 来源双路径 | 路径 A：人物页主动「+ 写一条经历」；路径 B：Post @ 后 toast 询问 |

### 4.7 备份规则

| 规则 | 说明 |
|------|------|
| 主推导出 / 导入 | .zip / .json 文件作为主路径 |
| 云同步次级 | 折叠区，默认收起 |
| 协议白名单（底层） | WebDAV / S3 兼容；UI 不暴露 |
| 单向上传 | 不做跨设备合并；恢复需整体覆盖 |
| 加密可选 | 启用加密后口令仅本地保留（keychain） |
| 失败静默 | 自动备份失败重试 ≤3 次，不弹窗 |

### 4.8 文案规则

| 类型 | 规则 |
|------|------|
| 主叙事 | 「你已经活了 N 天」「✓ 打卡」「今天还没留下任何痕迹」「想写点什么吗？」 |
| 备份叙事 | 「网盘服务」「网盘地址」「测试一下」「上传前加密保护」 |
| 提醒邮件 | 「温柔提醒」「牵挂」「确认 ta 是否安好」 |
| 错误提示 | 必须温和；「地址写错了？」「账号或密码不对？」 |

#### 禁用词清单

以下词不得出现在任何用户可见 UI / 默认模板中：

**社交叙事**：匹配码 / 关心绑定 / 关心动态 / 互绑 / 解除绑定 / 公共故事 / 投稿 / 订阅作者

**沉重叙事**：死亡 / 诅咒 / 已故 / 终结 / 离世 / 生存确认

**技术术语**：
- 协议：WebDAV / S3 / endpoint / region / accessKeyId / secretAccessKey / 对象存储 / bucket
- 加密：AES-256-GCM / PBKDF2 / iv / salt / 端到端 / E2EE
- 数据库：SQLite / IndexedDB / SHA-256 / dump
- 编辑器：Markdown / .md / 草稿 / 自动保存于（仅 web 桌面编辑器例外）

**旧风格遗留**：Herbarium / Specimen / Anno MMXXVI / Cotidie / Caveat

## 5. 技术架构

### 5.1 整体架构

```
┌────────────────────────────────────────────────────────┐
│                   客户端（本地优先）                    │
│ ┌──────────────────────────────────────────────────┐  │
│ │  UI Layer (RN / React / Taro)                    │  │
│ ├──────────────────────────────────────────────────┤  │
│ │  Domain Layer (Post / Event / Person / Reminder) │  │
│ ├──────────────────────────────────────────────────┤  │
│ │  Storage Layer                                    │  │
│ │ IndexedDB (Web)                               │  │
│ │ SQLite + Sandbox FS (App)                     │  │
│ ├──────────────────────────────────────────────────┤  │
│ │  Backup Adapter（用户视角：「网盘」）             │  │
│ │ 加密（AES-256-GCM, 可选；用户称之为「加密保护」）│
│ │ 打包（manifest + db + media）                 │  │
│ └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
         │（HTTPS 仅鉴权 + 可选邮件中转）
         ▼
┌────────────────────────────────────────────────────────┐
│             轻后端 Server (Node + Postgres)            │
│ 用户账号鉴权（不存日记内容）                          │
│ 邮件转发（提醒邮件可选；用户也可走客户端 SMTP）       │
│ 不存任何 Post / Person / Reminder / Event / 媒体     │
└────────────────────────────────────────────────────────┘
         │（用户自选，UI 中称为「网盘」）
         ▼
┌────────────────────────────────────────────────────────┐
│         用户自建备份目标（标准协议，底层 WebDAV / S3）  │
│  Nextcloud / 坚果云 / MinIO / R2 / B2 / 自架等          │
└────────────────────────────────────────────────────────┘
```

### 5.4 数据模型概要

#### 5.4.1 客户端本地表

| 表 | 字段 |
|----|------|
| `posts` | id / createdAt / dayKey / body / photos / mentions / reminderId / **linkedEventId** / updatedAt |
| `events` | **id / title / description / participants / timeHint / sortKey / linkedPostId / createdAt / updatedAt** |
| `reminders` | id / title / targetDate / recurrence / relatedPersonIds / note / createdAt |
| `persons` | id / name / aliases / avatar / birthday / impression / biography / tags / themeColor / **customFields** / **relations** / **layoutHint** / createdAt / updatedAt |
| `mentions` | postId / personId |
| `daykeys` | dayKey / hasCheckin / firstActivityAt |
| `backupMeta` | protocol / config（加密存储）/ lastSyncedAt |
| `reminderEmailConfig` | enabled / mode / triggerDays / contactEmail / template |

字段说明：

- **`Person.customFields`**: `{ key: string; value: string }[]`，用户自定义键值对
- **`Person.relations`**: `{ targetId: string \| 'self'; type: string }[]`，到其它人物或"我"的关系
- **`Person.layoutHint`**: `{ x: number; y: number }`，关系图中用户拖动后的位置
- **`Event`**: 新增表，承载人物经历；与 Post 并列但用途不同
- **`Post.linkedEventId`**: 若该 Post 被用户选择"同时记为某人经历"，关联到生成的 Event

#### 5.4.2 服务器侧（最小集）

| 表 | 字段 |
|----|------|
| `users` | id / email / phone / passwordHash / nickname / createdAt |
| `userEmailConfig` | userId / smtpHost / smtpPort / smtpUser / smtpPassEnc（可选） |

服务器**不存** Post / Person / Reminder / Event / Mention / 备份内容。

## 6. 风险与限制

| 风险 | 缓解 |
|------|------|
| 用户多设备并发写入冲突 | MVP 不做合并；UI 明示「备份是单向快照」；提供「从备份恢复」红色二次确认 |
| 状态机隐藏写入入口可能让新用户迷失 | 未打卡卡片下方加引导小字"先打个卡，再聊点什么"；动效让因果关系清楚 |
| 云端配置门槛仍存在 | 提供坚果云 / Nextcloud 配置模板；测试连接给具体错误提示 |
| @ 误解为社交动作 | 首次 @ 一次性 toast 解释 |
| 关系图节点 > 30 拥挤 | 用户可拖动重布局；提供「隐藏孤立」开关 |
| 自由 timeHint 无法做时间筛选 | MVP 放弃；后续可加智能识别 |
| 去技术化反而让进阶用户不知道用什么协议 | 设置→关于 折叠区列出「技术细节」 |

## 8. 隐私与安全

### 8.1 隐私保护

| 规则 | 说明 |
|------|------|
| 本地优先 | 默认所有 Post / Event / Reminder / Person / 媒体 仅存于设备 |
| 服务器不存 | 后端仅鉴权与可选邮件中转，不存日记内容 |
| @ 不推送 | @ 提及为本地索引，不向他人发送任何信息 |
| 备份目标自选 | 用户决定备份去哪，不锁定云厂商 |
| 客户端可加密 | 启用「上传前加密保护」后服务器侧只存密文 |
| 传输 HTTPS | 所有网络通信强制 TLS 1.2+ |
| 无第三方追踪 | 不使用第三方统计工具 |

### 8.2 数据导出 / 删除

- 用户可一键导出全部数据（备份包格式）
- 用户删除账号 → 服务器侧账号记录删除；本地数据由用户自主清理
- 用户可从备份恢复整体数据（覆盖式 + 红色二次确认）
